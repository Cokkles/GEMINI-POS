# GPOS Android 0.1 — Authentication & Connectivity Implementation Status

Status: implementation checkpoint in validation

## Implemented

### Production AUTH-1 contract alignment

Android now models the production AEGIS AUTH-1 transport used by the PWA:

- public `GET ?action=auth_config`
- protected `POST` JSON transported as `text/plain;charset=utf-8`
- Google ID token carried as `auth_token`
- `auth_login`
- `auth_session`
- `auth_logout`
- bounded read-only protected actions currently exposed to Android:
  - `get_health`
  - `get_dashboard`
  - `get_capabilities`
  - `get_latest_horizon`

The Android transport does not expose calendar/task/finance/model-generation mutations.

### Native Google sign-in

Android uses Credential Manager with Sign in with Google to request a Google ID token for the configured AUTH-1 server audience. The token is passed directly to the AUTH-1 transport boundary and is never inserted into Compose UI state or diagnostics.

The Android package/signing certificate may still need to be registered in the Google Auth Platform for native sign-in on a physical device. A developer/configuration error at sign-in is treated as an authentication configuration issue, not as permission to weaken AUTH-1 validation.

### Credential custody

Authenticated ID tokens are persisted only through `AndroidKeystoreCredentialStore`:

- AES-256/GCM
- key generated and retained in Android Keystore
- encrypted payload only in private SharedPreferences
- expired/rejected credentials are removed
- sign-out clears local protected state even when remote logout fails

### Runtime diagnostics

System now separates:

1. Android OS connectivity
2. public AUTH-1 backend discovery
3. authentication state
4. protected health/dashboard read check
5. canonical HORIZON source state
6. remaining fixture/canonical mapping state

This prevents a network, OAuth, authorization, mapping, or cache problem from being presented as the same failure.

### 0.1-D first canonical cutover — HORIZON

The first bounded production read mapping is implemented for `get_latest_horizon` because the production PWA already establishes `plain_text` as the canonical briefing payload.

After successful AUTH-1 authentication Android:

1. requests `get_latest_horizon`;
2. requires non-empty `plain_text`;
3. stores the complete bounded JSON response as last-known-good data in Room under a dedicated `latest_horizon` cache key;
4. records fetch/freshness metadata;
5. renders the briefing as `LIVE` on success;
6. falls back to Room as `CACHED` or `STALE` on bounded read failure;
7. never treats that Android cache as canonical authority.

The Briefing screen can therefore become genuinely useful while offline after at least one successful authenticated fetch.

Calendar, Tasks, Follow-ups and Finances remain deterministic fixtures until their production response shapes are validated with equal confidence. The UI explicitly labels that boundary.

## Checkpoint signing transition

The Android GitHub Actions workflow now preserves a stable development debug signing identity through a dedicated cache key and publishes the APK signing SHA-256 fingerprint with each artifact.

Because prior checkpoint APKs were built before this policy existed, the first install from the new signing baseline may require uninstalling the older GPOS development APK if Android reports a signing mismatch. Subsequent checkpoint builds using the retained signing identity are intended to support in-place upgrades.

## Next implementation increment

Continue 0.1-D by validating the authenticated `get_dashboard`, health and capability response shapes and mapping only proven fields into bounded Android read models.

The next likely progressive cutovers are Calendar/Tasks and then Follow-ups/Finances, each retaining explicit LIVE/CACHED/STALE/OFFLINE provenance.

## Stop conditions still active

Do not unilaterally:

- add a new production OAuth trusted audience;
- weaken AUTH-1 audience/email/expiry/issuer validation;
- add protected mutation commands to the Android transport;
- change PWA/Desktop required request semantics;
- trigger HORIZON/model generation in background synchronization;
- treat cached Android data as canonical authority.
