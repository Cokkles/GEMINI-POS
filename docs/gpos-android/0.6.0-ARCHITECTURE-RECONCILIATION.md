# AEGIS Android 0.6.0 — Architecture & Contract Reconciliation

Status: **IMPLEMENTATION AUTHORIZED**

## Purpose

0.6.0 is the daily-use workflow simplification and shared-contract parity phase. The Android client remains a first-class native client and does not depend on the Windows helper/application.

Core invariant: **READ AUTOMATICALLY. MUTATE EXPLICITLY.**

## Canonical shared-backend baseline

The current backend reference supplied for this phase identifies itself as **AEGIS backend 2.6.5**. Android must consume the existing contracts rather than reshape shared Apps Script behavior for mobile convenience.

No shared backend modification is authorized or required by this checkpoint.

Any future backend change required by Android must:

1. be additive/versioned or capability-gated where appropriate;
2. preserve existing Windows and PWA request/response behavior;
3. retain AUTH-1 and existing scope boundaries;
4. be recorded as a shared-backend change in the Android and Windows development records;
5. be reviewed before deployment when it changes a shared contract;
6. avoid sweeping refactors merely to support one client.

## Deliberate contract gaps

### Google Task hard delete/edit

Backend 2.6.5 exposes generic Task creation and Task completion, but no dedicated generic `delete_task` or `edit_task` contract is advertised. Android 0.6 must **not invent one** and must not repurpose another route.

0.6 therefore supports:

- create a Google Task;
- check off / complete an existing Google Task through the existing delayed synchronization queue;
- Undo during the local five-minute grace period;
- explicit Sync & Refresh.

Hard delete/edit remains a shared-backend review item for a future phase.

## 0.6 information architecture

### Home

Home is a glanceable dashboard rather than an input workspace:

- date and compact connection/auth indicator;
- quote;
- HORIZON freshness;
- today's agenda;
- compact Tasks summary;
- compact nutrition summary;
- Headliners;
- attention/alert summary.

Capture forms do not occupy Home.

### Calendar

Month + selected-day agenda plus one natural-language AEGIS Calendar control. READ requests answer directly. CREATE/UPDATE/DELETE requests require the backend `calendar_ai` preview and a one-shot `calendar_confirm` before mutation.

### Tasks

Active Google Tasks, Add Task, delayed completion/Undo, Sync & Refresh. No unverified hard-delete API.

### Capture

Dedicated high-frequency submission surface with four primary actions:

- Note
- Journal
- Calories
- Receipt

Every successful submission must show in-app confirmation, create the existing protected local receipt, and use Android outcome notifications when permission is granted.

### News & Insights

- Headliners at the top.
- Remaining categories collapsed by default and individually expandable.
- Story selection opens the supplied URL through Android's standard external URL handling, so the user's configured default browser is used.

### More

- Ask AEGIS
- Follow-ups
- News & Insights
- Nutrition
- Alerts & Receipts
- HORIZON
- Finances
- Search
- Diagnostics & Settings

## Authentication continuity

The existing encrypted credential/session restoration remains authoritative. 0.6 adds a best-effort native Credential Manager renewal path for a previously authenticated account when the local Google ID token has expired. Explicit Sign out clears both protected local state and the continuity marker.

Connectivity and authentication must remain distinct presentation states: loss of network does not imply the user signed out.

## Rollback

`ParityActivity` remains the launcher shell, while the prior parity UI implementation and earlier `DailyDriverActivity` / `GposActivity` surfaces remain available in source as rollback points. 0.6 replaces only the active Compose surface and adds typed client contracts; it does not delete the prior implementations.
