# Android 0.8.0 — Phase 3 Capture + Running Notes

## Combined workspace

The Notes bottom tab and the legacy Running Notes deep link now open the same
protected workspace:

- the long-form Running Notes editor saves locally on every edit;
- `ParityActivity.onStop()` explicitly flushes the current draft when the app
  leaves the foreground;
- Journal sync remains optional, manual, previewed in plain language, and never
  runs merely because the screen was opened;
- one-time Note, Journal, Nutrition, and Receipt capture stays available below
  the running draft.

## Pending and recovery controls

- A pending Journal submission retains its stable submission ID and original
  section for a safe retry.
- The user may verify that the entry already exists in the Journal, or clear the
  pending marker while restoring the complete section to the local editor.
- Clearing a pending marker never sends a network request and never discards the
  draft.
- Recovery history remains collapsed by default and keeps checkpoints, synced
  sections, restored copies, and cleared-pending copies.

## Capture queue controls

- Active receipts appear inline with queued/waiting/review/error details and the
  stable capture-ID prefix.
- Eligible receipts expose Retry or Check/retry.
- Clear is explicit and unavailable while a receipt is actively sending or
  already confirmed.
- Clearing cancels future local work, scrubs the stored payload, marks the
  receipt cancelled, and does not claim that a server-managed capture was
  cancelled remotely.
- Clear resolved removes only confirmed/cancelled receipts and acknowledged
  local alerts. Active work is preserved.

## Rollback

Phase 2 commit is the direct rollback point for Capture/Notes behavior. Android
0.7.6.1 remains the packaged release rollback and backend 2.8.4.1 remains the
production script rollback.
