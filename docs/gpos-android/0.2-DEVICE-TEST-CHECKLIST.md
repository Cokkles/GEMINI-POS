# GPOS Android 0.2 — Device Test Checklist

Version target: `0.2.0-dev` (`versionCode 3`)

## 1. Upgrade install

1. Install the 0.2 APK over the signed 0.1 checkpoint.
2. Confirm Android accepts it as an update rather than a separate application.
3. Launch GPOS.
4. Confirm the selected theme from 0.1 remains selected.
5. Confirm the Quote of the Day remains visible at the top of Home.

If an older pre-signing-baseline A0 APK is installed, Android may require one uninstall/reinstall. Signed 0.1 → 0.2 should upgrade in place.

## 2. Signed-out state

Expected:

- app launches normally;
- Home does not present fixture events/tasks as canonical truth;
- dashboard status is `NOT LOADED` unless a prior authenticated cache exists;
- Briefing, Calendar and Tasks remain navigable;
- System shows backend/authentication diagnostics;
- no remote mutation controls are available.

## 3. Authentication

Open `More → System`.

1. Confirm backend discovery reports reachable/configured AUTH-1 when online.
2. Tap `Sign in with Google`.
3. Choose the authorized Google account.
4. Confirm the app reports `Signed in`.
5. Tap `Canonical` or the top refresh icon.

If Google returns a developer/configuration error, capture the exact message. Android OAuth registration may require:

- package: `com.cokkles.gpos`
- signing SHA-1 from the checkpoint artifact
- signing SHA-256 from the checkpoint artifact

Do not weaken AUTH-1 validation to work around a native OAuth registration issue.

## 4. Home canonical dashboard

After successful authentication/refresh, confirm:

- `Dashboard • LIVE` appears;
- next event is based on the canonical today/tomorrow feed;
- active task count reflects the canonical task feed;
- first task titles are real current tasks;
- HORIZON generation metadata is shown when returned;
- no fixture warning/sample data is presented as canonical truth.

Compare visible event/task counts with the current AEGIS PWA for a sanity check.

## 5. Briefing

Open `Briefing`.

Confirm:

- source shows `LIVE` after a successful read;
- HORIZON title/sections/subsections render as mobile cards;
- bullets are readable;
- raw Markdown presentation characters are reduced without changing wording;
- no new tasks/calendar facts are inferred from the briefing text;
- `Refresh briefing` triggers read-only refresh behavior.

## 6. Calendar

Open `Calendar`.

Confirm:

- source provenance is visible;
- Today events match the canonical dashboard feed;
- Tomorrow events match the canonical dashboard feed;
- time/title/note are readable;
- no edit/create/delete controls exist in 0.2.

## 7. Tasks

Open `Tasks`.

Confirm:

- source provenance is visible;
- active task titles match the canonical dashboard feed;
- the `Read-only in 0.2` safety card is visible;
- there are no completion/edit/delete mutation controls.

## 8. Theme regression

Open `System → Appearance` and cycle through:

- GPOS Light
- GPOS Dark
- Monokai
- Dracula
- Solarized Dark
- Nord

For each theme verify:

- body text is clearly legible;
- navigation selected/unselected states are distinguishable;
- source/status cards remain readable;
- buttons retain adequate contrast;
- HORIZON section text remains readable.

Return to the preferred theme and restart the app to confirm persistence.

## 9. Offline dashboard fallback

Prerequisite: complete at least one successful authenticated LIVE dashboard read.

1. Disable network connectivity.
2. Fully close and reopen GPOS.
3. Confirm cached dashboard data remains available.
4. Confirm source is `CACHED` when the cache is within 30 minutes.
5. After the freshness window expires, confirm the source is `STALE` rather than falsely `LIVE`.
6. Confirm refresh failure does not erase the last-known-good payload.

## 10. Offline HORIZON fallback

Prerequisite: complete at least one successful LIVE HORIZON read.

With connectivity disabled:

- Briefing remains readable from Room;
- source reports `CACHED` while within the 24-hour HORIZON freshness window;
- source reports `STALE` after that window;
- failed refresh does not trigger HORIZON generation.

## 11. Explicit sign-out privacy behavior

After LIVE data has been loaded:

1. Open `System`.
2. Tap `Sign out`.
3. Confirm authentication state becomes signed out.
4. Return to Home/Calendar/Tasks/Briefing.
5. Confirm private cached dashboard/HORIZON content is no longer displayed.
6. Disable network and restart the app.
7. Confirm signed-out private content does not reappear from Room.

This is intentional: offline resilience applies to an active/restorable session, while explicit sign-out clears private local cache.

## 12. Read-only safety audit

During the entire 0.2 test verify Android does not:

- complete Google Tasks;
- create/edit/delete Calendar events;
- write financial records;
- invoke Ask AEGIS/model generation;
- trigger HORIZON generation;
- trigger PRISM reconciliation;
- acknowledge or mutate notification state;
- claim a failed remote write succeeded.

## Pass condition

0.2 device validation is considered successful when:

- upgrade installation succeeds from the signed 0.1 baseline;
- authentication works or any OAuth-registration blocker is precisely identified;
- canonical dashboard/HORIZON reads render correctly;
- Calendar and Tasks match the backend/PWA;
- offline cache provenance behaves correctly;
- explicit sign-out clears private cache;
- navigation/themes remain smooth and readable;
- no unintended mutation occurs.
