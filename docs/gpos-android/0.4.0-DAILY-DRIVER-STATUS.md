# GPOS Android 0.4.0 — Daily Driver Expansion

## Goal

0.4.0 shifts Android from a contract-validation shell into a useful daily GPOS client while preserving the proven AUTH-1, canonical cache, background-read, and explicit-mutation boundaries.

The governing rule remains:

> **READ AUTOMATICALLY. MUTATE EXPLICITLY.**

## Launcher architecture

0.4 introduces `DailyDriverActivity` as the launcher and deep-link target.

The 0.3 `GposActivity` remains compiled and declared as a non-exported rollback activity. This is deliberate: the daily-driver UI can be reverted without deleting the validated 0.3 implementation.

## Daily-driver surfaces

### Today

The Home destination is now presented as **Today** and combines currently synchronized canonical domains:

- authenticated identity / current date;
- compact Dashboard / HORIZON / Finance provenance;
- next today/tomorrow event;
- today's agenda preview;
- active task preview;
- current HORIZON headline and generation timestamp when available;
- server-alert summary with critical-attention signal;
- recent SENTINEL-FIN totals;
- direct navigation from cards to the detailed domain;
- explicit Sync now action.

### Search

0.4 adds a local-only cross-domain search surface over data already synchronized to the device:

- today/tomorrow Calendar events;
- active Google Tasks;
- canonical HORIZON section titles/content;
- recent finance transactions;
- active server notifications.

Search performs no network call and no AI/RSS generation. Results deep-link to their source GPOS area.

### Briefing

Canonical HORIZON remains read-only. Sections are rendered natively and can be collapsed/expanded for practical mobile navigation.

### Calendar

The Today/Tomorrow agenda remains canonical. The existing explicit two-stage write contract remains intact:

1. describe event;
2. Resolve & preview (no Google Calendar write);
3. review structured proposal;
4. explicit Add to Google Calendar.

### Tasks

Tasks are organized into scheduled and unscheduled groups using only the bounded dashboard fields currently available. Task selection remains local staging. Completion still requires explicit confirmation and fresh canonical verification.

### Finances

SENTINEL-FIN remains read-only. 0.4 adds:

- purchase / credit summary;
- transaction count;
- category pulse calculated locally from the bounded 72-hour transactions;
- richer recent transaction list.

No finance mutation is exposed.

### Notifications

Active alerts are ordered by severity and recency. Critical state is surfaced prominently. Acknowledgement remains explicit and foreground-only; opening a screen or deep link never acknowledges.

Critical Android notification PendingIntents now target the 0.4 DailyDriverActivity, so deep links enter the active daily-driver Notifications route rather than the retained rollback activity.

### System

Normal System UI now emphasizes:

- backend connection;
- Google/auth state;
- per-domain sync provenance;
- bounded background sync policy;
- Android notification permission;
- appearance.

Package, signing SHA-1 and OAuth client diagnostics have been moved behind **Show developer diagnostics** so they do not dominate ordinary use.

## Still gated

0.4.0 does not invent new canonical write contracts. These remain gated pending explicit shared-contract review:

- Google Task create/edit/delete;
- Calendar edit/delete;
- finance writes;
- Follow-ups canonical state changes;
- Ask AEGIS conversational command transport;
- HORIZON generation;
- PRISM execution;
- RSS/Intelligence refresh;
- arbitrary/background mutation.
