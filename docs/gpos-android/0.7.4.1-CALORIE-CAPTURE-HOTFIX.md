# AEGIS Android 0.7.4.1 — Calorie Capture Hotfix

## Outcome

Android now sends Meal / Calories text to Apps Script exactly as entered, after trimming only leading and trailing whitespace. It no longer converts comma- or newline-separated foods into Unicode bullet items.

## Evidence and scope

- The Android 0.7.4 attempt reached the canonical nutrition ledger but produced a zero-macro fallback row after its transformed bullet-list input failed Gemini parsing.
- The same deployed Apps Script 2.8.0 route successfully parsed a subsequent PWA submission.
- This hotfix is Android-only. Apps Script 2.8.0 and all shared-backend contracts remain unchanged.
- Android continues to reject `macros pending` and other unconfirmed results so a zero-macro fallback is not presented as a successful meal.

## Regression boundary

- Preserve single-item wording.
- Preserve comma-separated multi-item wording.
- Preserve newline-separated multi-item wording.
- Do not change Note, Journal, or Receipt capture text beyond outer whitespace trimming.
- Do not add automatic retries for ambiguous writes.
