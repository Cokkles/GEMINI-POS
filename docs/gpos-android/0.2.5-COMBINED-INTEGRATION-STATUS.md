# GPOS Android 0.2.5 — Combined Integration Status

## Sprint scope

This checkpoint combines the planned 0.2.1 through 0.2.5 increments into one broad read-oriented Android integration pass.

Core rule remains:

> **READ AUTOMATICALLY. MUTATE EXPLICITLY.**

No new canonical write operation is exposed by this checkpoint.

## 0.2.1 — Native OAuth stabilization

Implemented:

- deterministic development/checkpoint signing identity
- package/SHA identity visible in System diagnostics
- Credential Manager error classification
- explicit likely Android OAuth registration diagnostic
- AUTH-1 remains the backend authentication authority
- existing Web/server OAuth client remains the ID-token audience
- no AUTH-1 weakening or bypass

External provisioning still required:

- register Android OAuth client for `com.cokkles.gpos`
- checkpoint SHA-1 `D2:A0:80:66:49:D0:00:B1:B8:4F:FF:45:A9:C6:DF:76:8D:FC:31:EA`

## 0.2.2 — Canonical dashboard expansion

Implemented:

- Home morning dashboard
- latest today/tomorrow event summary
- active task count/preview
- HORIZON availability/status
- explicit LIVE / CACHED / STALE provenance
- independent bounded cache freshness by domain

## 0.2.3 — Additional read-only domains

### SENTINEL-FIN recent activity

Implemented from the existing production PWA contract:

- `get_recent_finance`
- 72-hour window
- `summary.purchaseTotal`
- `summary.creditTotal`
- transactions: vendor, amount, category, paymentSource, occurredAt, notes
- independent Room last-known-good cache

### Server notifications

Implemented from the existing production PWA contract:

- `get_notifications`
- title/message/severity/type/detail/createdAt/acknowledged
- active/unacknowledged view
- critical-count Home summary
- independent Room last-known-good cache

Acknowledgement is intentionally not exposed because it is a mutation.

### News & Insights

Implemented as a zero-generation projection of matching sections from the already-fetched canonical HORIZON document. The Android app does not trigger Intelligence/RSS refresh to populate this view.

### Still gated

- dedicated Follow-ups contract
- Ask AEGIS conversational transport

## 0.2.4 — Mobile platform behavior

Implemented:

- periodic WorkManager read refresh every 30 minutes
- network-connected constraint
- battery-not-low constraint
- only runs with a still-valid encrypted credential
- no interactive auth from background worker
- dashboard read
- finance read
- notification read
- HORIZON read only when its daily cache is stale/missing
- bounded retry for read failures
- authentication rejection clears protected credential/cache
- no Gemini generation
- no HORIZON generation
- no PRISM action
- no RSS/Intelligence refresh
- no task/calendar/finance mutation

Notification behavior:

- Android notification permission is explicit
- local critical alert uses generic privacy-safe text
- private server message is not copied into lock-screen notification
- tapping notification deep-links to the allowlisted Notifications route
- deep-link payload does not carry private content

- preserved offline Quote of the Day
- expanded System diagnostics
- OAuth package/SHA registration guidance in-app
- cache provenance for Dashboard, HORIZON, Finance, Notifications

- instrumentation navigation coverage updated for new surfaces

- notification mapper unit tests

## Explicitly deferred to 0.3

The following remain outside this combined sprint:

- completing/editing Google Tasks
- calendar creation/update/delete
- notification acknowledgement
- finance writes
- Follow-ups mutation/state changes
- Ask AEGIS command/query transport
- any automatic expensive generation operation

Those features require an explicit mutation/idempotency/confirmation review before Android exposes them.
