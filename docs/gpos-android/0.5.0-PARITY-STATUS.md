## Read and mutation boundary

The standing rule remains:

**READ AUTOMATICALLY. MUTATE EXPLICITLY.**

Automatic/background behavior remains bounded to protected canonical reads. It must not trigger HORIZON generation, PRISM execution, RSS/Intelligence generation, finance writes, arbitrary AEGIS actions, or any other expensive/shared mutation.

The finite explicit command surface currently includes:
1. Google Task completion.
2. Calendar event resolve/preview then explicit create.
3. Server notification acknowledgement.
4. Explicit foreground Capture submission.

The command client still intentionally exposes no generic `execute(action)` or arbitrary action API.
