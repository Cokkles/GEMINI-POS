## Changes

Shortcuts and tabs now share navigation handling. Tapping a tab opens its named root; a previously visited Search or Alerts child cannot be restored instead. Secondary pages retain normal Back navigation. Existing transient form state is not promoted to unencrypted persistent storage.

Keystore reads/writes and HTTP response decoding run off the UI dispatcher. Repeated canonical refreshes share each domain's active request, full parity refresh is single-flight, and the toolbar shows refresh progress. Calendar responses from an older month request cannot replace the currently selected month. Calendar grouping is memoized per snapshot.

Settings & Diagnostics exposes an explicit expandable, selectable raw HORIZON text view, rendered in bounded lazy chunks. It reads the already retrieved canonical `plain_text`; it does not generate a report or reveal authentication tokens. Backend version is visible.

Google continuity waits for actual stored-session restoration (up to the combined transport deadlines), is checked on foreground resume, and can renew a token approaching expiration through the previously authorized Google-account flow. A transient renewal exchange failure preserves a still-valid stored session. Explicit logout cancels the automatic attempt. No token lifetime is extended, no expired token is treated as valid, and backend authorization/configuration errors are not automatically retried. Google can still require account selection or reauthentication.

The client recognizes the baseline's `additional_audiences_configured` flag. A different public default client ID no longer blocks an advertised multi-client configuration locally; AUTH-1 remains the authority for accepting or rejecting the supplied Google token.

## Cross-client compatibility

No Apps Script code, deployment, AUTH-1 policy, scope, endpoint, payload semantic, Windows source, PWA source, or canonical data was changed. All work is Android-local. No HORIZON generation, finance ingestion, receipt submission, Calendar write, or Task write is executed during development validation.

Backend 2.7.0 advertises `task_crud_v1`, `task_workspace_v1`, `tasks_history_v1`, `task_lists_v1`, and `calendar_prepare_v1` in addition to earlier contracts. These are recorded for the next workspace phase; 0.6.1 does not assume feature completion merely from their presence.

Any future shared change must record endpoint/contract, Windows/Android/PWA/Helper impact, compatibility/versioning, client changes, rollout order, and rollback before implementation. Rule: **PROPOSE FREELY. BREAK NOTHING SILENTLY. VERSION DELIBERATELY. COORDINATE ALL CLIENTS.**

## Validation and next phases

CI gates: Android lint, JVM unit tests (including expiry/logout/error continuity decisions), both APK builds, package/version/certificate checks, and emulator regression tests against the actual `ParityActivity` launcher. The obsolete DailyDriverActivity-only smoke test is replaced.

The next acceptance gate is device testing of 0.6.1. Then 0.6.2 adds protected explicit HORIZON generation controls, followed by 0.7 Task workspace and Calendar completion against verified 2.7.0 contracts. The remaining Windows brief items remain roadmap requirements, not completed Android features.

Rollback: the untouched 0.6.0 parent branch is the source checkpoint. If a binary rollback is needed, prefer rebuilding that source with a higher Android versionCode; Android may reject direct APK downgrades, and uninstalling removes local data.
