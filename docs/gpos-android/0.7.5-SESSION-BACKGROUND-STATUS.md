# AEGIS Android 0.7.5 — Session & Background Reliability

## Outcome

Android now restores a still-valid authenticated profile from the existing Keystore-protected credential immediately, validates it quietly, and keeps automatic reads out of the global loading indicator. Periodic canonical reads run every 15 minutes under Android WorkManager constraints. Timed events already fetched from Calendar are mirrored into local 60-minute and 15-minute reminders for the next seven days.

## Reliability behavior

- A successful AUTH-1 validation stores the user profile, token expiry, and validation time inside the encrypted credential envelope.
- On later launches, a valid stored profile can render as connected immediately while the server validation continues in the background.
- Older 0.7.4.2 credentials remain compatible. The first successful validation upgrades their encrypted envelope with the profile fields.
- Automatic session and parity refreshes do not hold the top progress bar across screens. Explicit user refreshes remain visible.
- Canonical WorkManager reads run every 15 minutes when Android allows them and the current Google authorization remains valid.
- Pending task and capture queues remain local and resume after successful Google renewal.
- Calendar refreshes schedule best-effort local reminders at 60 and 15 minutes for timed events in the next seven days. All-day events are excluded.
- A refreshed deletion cancels matching pending reminders. A changed event replaces reminders for the same event ID. The worker rechecks the latest Calendar cache before displaying a named reminder.
- Explicit sign-out still clears protected local state and cancels scheduled Calendar reminders.

## Security and platform boundary

Google ID tokens are intentionally short-lived; Android does not cache or extend one indefinitely. Silent renewal still uses the previously authorized Google account through Credential Manager while the Activity is resumed. If authorization expires while the app is closed, queued mutations remain preserved and AEGIS requests foreground renewal instead of using an invalid credential.

WorkManager and Android power management make background timing best-effort rather than exact. Local reminders improve closed-app coverage for already-known events, but they do not replace a server push channel or an additive renewable AEGIS session contract.

## Compatibility

- Android: `0.7.5-dev` (`versionCode 19`)
- Apps Script baseline: `2.8.0`, unchanged
- Backend contracts: unchanged; no Android-only backend dependency added
- Upgrade path: install over 0.7.4.2 without uninstalling
