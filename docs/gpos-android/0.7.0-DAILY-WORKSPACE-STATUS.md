## Agreed scope

- Google Tasks workspace across lists; filter; task create/edit/delete; list create/rename; 7/30-day completed history and restore; five-minute completion Undo with list identity throughout the queue.
- Encrypted, account-bound Running Notes with continuous local autosave, recovery checkpoints, copy/share, explicit journal submission and a fresh section only after confirmed success.
- News category dividers/collapse and persistent Headliners eligibility; Deals excluded by default. Android display preferences only; do not alter shared HORIZON selection.
- Home Calendar shortcut and a visual hierarchy pass: dark navy surfaces, section accents, borders, compact quote and freshness indicator, clearer typography.

## Contract review and boundaries

Read automatically. Mutate explicitly. No backend edits or deployments, no Windows Helper dependency. Discover task capabilities at runtime. Existing 2.7.0 task workspace enumerates up to 25 lists and 100 active tasks per list; history up to 100 per list / 200 total. Android cannot claim unlimited pagination until the shared contract is extended and coordinated.

Windows sends tagged `/note [RUNNING_NOTES]` entries to the canonical Notes & Ideas Log with a stable submission ID. The supplied Apps Script does not implement submission-ID deduplication. Android must preserve an uncertain submission, never automatically resend it, and require explicit review before retry; stable IDs alone cannot guarantee server deduplication. Record a future additive idempotency proposal, not an unreviewed backend change.

No list deletion, automatic draft submission, HORIZON generation, or shared preference synchronization in this release. These boundaries preserve existing cross-client authority.

## Validation gates

Build, lint, JVM tests, real-launcher emulator navigation, account-bound storage/restart tests and task/list payload tests. Package with the existing deterministic signer and increment versionCode. User device acceptance: multiple lists and CRUD, history/restore, completion/Undo, offline notes/reopen/journal sync, Headliners preferences, readability and Calendar navigation.

## Acceptance and practical limits

Follow `0.7.0-DEVICE-TEST-CHECKLIST.md`. Real Google task/list mutations, journal contents, OS background timing and physical-device readability remain user acceptance checks. The component screenshots verify layout/export but omit the launcher Scaffold's background/content-color provider; they are not faithful full-screen color previews. The launcher itself supplies the dark surface and foreground through Scaffold. Do not present those fixture images as the shipped app's appearance.

Running Notes are device-local drafts, not automatic Windows/Android draft mirroring. Explicit sync appends to the same canonical Notes & Ideas Log used by Windows. Successful submissions retain the original submission ID in the local recovery revision. Appended edits after an uncertain request remain as the next draft; arbitrary rewrites are retained for review. No backend deduplication claim is made; see `RUNNING-NOTES-IDEMPOTENCY-PROPOSAL.md`.

The next development phase follows device acceptance. Protected HORIZON generation, deeper Calendar workflows and the remainder of the Windows parity brief remain future work.
