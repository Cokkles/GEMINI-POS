- [ ] Calendar loads canonical data.
- [ ] Month navigation works.

## 6. Tasks

- [ ] Active tasks render correctly.
- [ ] Task grouping/history controls behave normally where data is available.
- [ ] Staging a completion does not immediately perform an uncontrolled remote mutation.

- [ ] No unrelated task changes occur.

## 7. Capture

This is a new explicit foreground command surface included in the finite mutation boundary.

- [ ] Capture screen loads only while app is in the foreground.
- [ ] Select each available capture kind that is appropriate for testing.
- [ ] Blank/meaningless submissions are rejected or remain safely local.
- [ ] Explicit Submit sends only after the user action.
- [ ] A useful result/receipt is shown for a successful submission.
- [ ] Failure produces a clear error/receipt instead of silent success.
- [ ] Background sync does not submit Capture content automatically.

- [ ] One domain failing does not blank unrelated domains.
- [ ] Background read sync remains bounded and does not execute Capture, Task completion, Calendar create, notification acknowledgement, HORIZON generation, PRISM, RSS, or finance writes.

## 16. Physical UI fit

- [ ] Test portrait orientation on the normal phone size.

- [ ] Verify cards/text are not clipped at common display/font scaling.
- [ ] Verify dialogs/previews fit above system UI.
- [ ] Verify keyboard opening does not permanently hide required action buttons.

## Pass criteria

Declare **0.5.0 PHYSICAL-DEVICE PASS** when:
1. Install/update, launcher identity, splash, authentication, and canonical sync are healthy.
2. All major navigation surfaces are usable.
3. Existing explicit mutations remain properly confirmation-gated.
4. Capture behaves as an explicit foreground-only command.
5. Background behavior remains read-only/bounded.
6. No blocking layout/system-inset regression appears.
7. No crash, repeated auth loop, or canonical-data corruption is observed.

Record any failures with the screen/action, expected result, actual result, and whether the issue reproduces after force-close/reopen.
