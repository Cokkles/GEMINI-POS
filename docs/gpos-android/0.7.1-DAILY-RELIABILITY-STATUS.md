# AEGIS Android 0.7.1 Daily Reliability

Status: implementation checkpoint

## Delivered

- Google reconnect is now a recoverable session state. A transient sign-in or protected-read failure no longer erases the encrypted credential, canonical cache, task queue, capture receipts, or Running Notes draft.
- Explicit Sign out remains the only user action that clears identity-bound protected local state.
- Meal capture accepts comma, semicolon, and newline separated items and sends a structured list.
- Gemini retry orchestration is implemented with 60-second and 120-second delays, a three-attempt ceiling, encrypted pending payloads, stable submission IDs, and one final notification.
- Automatic retry stays disabled unless the backend advertises `AEGIS_CAPTURE_RELIABILITY_V1` and returns a typed `retryable=true`, `write_state=NOT_STARTED` capacity error. Apps Script 2.7.0 does not advertise this guarantee, so ambiguous writes are never repeated.
- Historical sections default collapsed and can be reopened; Running Notes no longer exposes the redundant Android share action.

## Backend boundary

Apps Script 2.7.0 is unchanged. The additive reliability proposal is documented separately and must preserve Windows and other client behavior before deployment.

## Validation target

- Android JVM tests
- Android lint
- debug APK and instrumentation APK assembly
- package, version, and checkpoint signing-certificate verification
