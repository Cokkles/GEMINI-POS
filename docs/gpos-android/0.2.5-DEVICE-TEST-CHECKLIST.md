# GPOS Android 0.2.5 — Device Test Checklist

## Installation / upgrade

1. If the phone still has the original ephemeral-signed 0.1 build, uninstall it once before installing the deterministic checkpoint line.
2. If a deterministic-signed 0.2 build is already installed, 0.2.5 should install as an in-place upgrade.
3. Confirm the app reports `GPOS Android 0.2.5-dev` on Home.

## Shell / appearance

- Home launches smoothly with Quote of the Day at the top.
- Bottom navigation works: Home, Briefing, Calendar, Tasks, More.
- System → Appearance changes the entire shell.
- Relaunch and confirm the selected theme persists.
- Check GPOS Light, GPOS Dark, Monokai, Dracula, Solarized Dark, and Nord for readable text/card/selected-state contrast.

## Native Google OAuth diagnostics

Open **More → System**.

Confirm the Android OAuth card reports:

- package `com.cokkles.gpos`
- checkpoint SHA-1 `D2:A0:80:66:49:D0:00:B1:B8:4F:FF:45:A9:C6:DF:76:8D:FC:31:EA`
- existing Web/server client ID.

Tap **Sign in with Google**.

Until the Android OAuth client is registered in Google Cloud, the expected useful outcome is an actionable native-configuration error rather than a generic failure.

After Android OAuth registration, validate:

1. Google account picker/consent completes.
2. AUTH-1 accepts the ID token.
3. System reports signed-in user.
4. Protected health/capability read succeeds.
5. Canonical refresh populates multiple domains.

If sign-in fails, record the exact diagnostic text. Distinguish whether it says Android OAuth configuration, provider/no credential/cancelled, or an AUTH-1 rejection.

## Home canonical dashboard

After authentication + refresh:

- Dashboard provenance should show `LIVE`.
- Next event should reflect canonical today/tomorrow Calendar data.
- Active task count/preview should reflect Google Tasks.
- Finance card should show 72-hour purchase/credit/activity summary when data exists.
- Server alert count should reflect unacknowledged notifications.
- HORIZON should report available and show current briefing content.

## HORIZON Briefing

- Briefing opens as native cards/sections rather than one raw text blob.
- Headings/subheadings are readable.
- Bullet content is readable in every theme.
- Refresh should fetch the existing latest canonical briefing only; it must not generate a new HORIZON briefing.

## Calendar

- Today and Tomorrow sections populate from the bounded dashboard feed.
- Empty dates show explicit no-events state rather than fixture data.
- No create/edit/delete controls are present.

## Tasks

- Active task titles populate from the canonical dashboard feed.
- Screen states clearly that it is read-only.
- No completion/edit controls are present.

## Finances

Open **More → Finances**.

- Provenance shows LIVE/CACHED/STALE.
- 72-hour purchase and credit summaries render.
- Recent transactions render vendor, amount, category, payment source, timestamp where present, and notes where present.
- No finance write/import/edit controls are present.

## Notifications

Open **More → Notifications**.

- Active/unacknowledged server notifications render.
- Severity is visible.
- The screen states that acknowledgement is deferred because it is a mutation.
- No server acknowledgement button is present.

### Android notification permission

In **System**, enable notifications.

The periodic worker will only post an Android notification when it observes a newly seen critical server alert. Lock-screen notification text should remain generic and should not copy private server content.

Tapping a GPOS Android notification should open the Notifications route.

## News & Insights

Open **More → Insights**.

- The screen should only project matching sections from the already-fetched HORIZON briefing.
- It must not claim to have refreshed RSS/news independently.
- If the current HORIZON has no matching news/insight/strategic sections, an explicit empty state should appear.

## Intentionally gated screens

### Follow-ups

Should clearly state that the dedicated contract is pending and should not manufacture follow-ups from Gmail/HORIZON heuristics.

### Ask AEGIS

Should clearly state that conversational transport is pending review; no command/query dispatch should be active yet.

## Offline / last-known-good test

After a successful authenticated refresh:

1. Close GPOS.
2. Disable network connectivity.
3. Reopen GPOS.
4. Verify still-valid protected local state can restore cached data.
5. Check provenance:
   - Dashboard/Calendar/Tasks: CACHED until 30 minutes, then STALE.
   - Finance: CACHED until 30 minutes, then STALE.
   - Notifications: CACHED until 5 minutes, then STALE.
   - HORIZON: CACHED until 24 hours, then STALE.
6. Verify the app does not claim a failed network refresh succeeded.

## Sign-out privacy test

After data has been cached:

1. Sign out explicitly.
2. Confirm private Dashboard/HORIZON/Finance/Notification content disappears.
3. Relaunch while signed out.
4. Confirm private cached content does not reappear.

## Background refresh behavior

After a valid authenticated session, GPOS schedules a 30-minute WorkManager read cycle constrained to:

- network connected
- battery not low

It may read:

- dashboard
- recent finance
- notifications
- HORIZON only if HORIZON cache is missing/stale

It must not trigger:

- HORIZON generation
- Gemini generation
- PRISM
- RSS/Intelligence refresh
- Google Task mutation
- Calendar mutation
- finance mutation
- notification acknowledgement
