# Android 0.8.0 — Elaborate Device Test Checklist

Record the APK SHA-256, installed version, backend version shown in Settings,
device model, Android version, and whether the install was clean or an upgrade.

## A. Upgrade and session continuity

1. Install over 0.7.6.1 without clearing app data.
2. Confirm Android reports AEGIS 0.8.0 (versionCode 23).
3. Cold-start twice and confirm there is no automatic Google account prompt.
4. Confirm the existing device session restores or the app gives a deliberate
   reconnect action.
5. Open Settings and record the reported backend version.

Expected: old protected drafts/queues remain available, sign-in identity is
unchanged, and 0.7.6.1 can still be reinstalled as the Android rollback.

## B. Calendar navigation and views

1. From Home, tap the Calendar heading, an event card, and the no-events link
   (when available). Each must open Calendar, not a prior child destination.
2. Switch Month → Week → Day → Agenda and return to Month.
3. Select a date in Month, then verify Week and Day center on that selection.
4. Change months, use Today, refresh, background the app, and reopen Calendar.
5. If backend 2.11.0 is deployed, switch All calendars and individual calendar
   sources; compare names/colors against Google Calendar.

Expected: views use one consistent snapshot, source filtering does not mutate
events, and opening/refreshing Calendar performs no write.

## C. Exact Calendar event

1. Open Create event and enter title, date, start/end time, location, and
   description.
2. Choose a recent-location suggestion, then edit it manually.
3. Select an owned calendar. Confirm shared read-only calendars are visible in
   views but not offered as write targets.
4. Tap Review exact event; inspect the preview, then Cancel.
5. Repeat and Confirm. Refresh Calendar and verify one event in Google Calendar.
6. Try an end time earlier than the start time and verify it is treated as an
   overnight event, not an invalid negative duration.

Expected: no event exists before Confirm; confirmation is one-shot; location and
selected owned calendar are preserved.

## D. Task lists, editor, and Undo

1. Switch among at least two task lists.
2. Create a list, rename it, and confirm Home list visibility controls still
   work.
3. Add a task with notes, due day, and reminder time.
4. Edit the task, remove only the reminder time, then remove the due day.
5. Complete a task, use Undo within two minutes, complete it again, and Sync.
6. Expand 7-day and 30-day history, restore a task, then collapse history.
7. Repeat one create/edit while offline; reconnect and use Sync queued.

Expected: list identity never falls back silently, reminder time survives a
refresh on backend 2.11.0, history starts collapsed, and Undo prevents the
queued completion from being sent.

## E. Running Notes and autosave

1. Type a multi-paragraph draft, leave with Home, background the app, then force
   stop and reopen.
2. Create a manual checkpoint and restore it.
3. Sync a section to Notes Journal and verify a fresh section opens only after
   confirmed success.
4. Simulate an uncertain sync (disconnect during submission), reopen, and
   inspect the pending state.
5. After checking the Journal, test both paths separately:
   - Entry verified;
   - Clear pending marker · keep draft.

Expected: the complete draft survives every exit; clearing a pending marker
sends nothing and restores all text to the editor.

## F. One-time capture queue

1. Queue one Note, Journal, Nutrition, and Receipt capture.
2. Immediately double-tap one submission and verify the stable original ID is
   reused.
3. Open Notes again and inspect inline queue states.
4. For a failed/review item, use Check/retry.
5. Clear one waiting/review item and confirm it leaves the active queue without
   claiming remote cancellation.
6. Confirm Clear is unavailable while an item is Sending.
7. Use Clear resolved and verify active items remain.

Expected: queued/pending/review states are distinguishable, payloads are scrubbed
when cleared, and active work is never removed by Clear resolved.

## G. Regression sweep

1. Refresh Home, HORIZON, News, Nutrition, Finances, Follow-ups, and Alerts.
2. Verify Nutrition is read-only on open and no reconciliation starts.
3. Lock/unlock, reboot, wait for background work, and verify notification deep
   links reach Calendar, Tasks, or Alerts correctly.
4. Sign out and verify protected local work is cleared only as part of the
   explicit sign-out flow.

Expected: no regression to authentication, navigation, notification routing,
nutrition capture, or read-only screens.
