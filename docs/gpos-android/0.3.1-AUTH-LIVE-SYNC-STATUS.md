# GPOS Android 0.3.1 — Authentication & Live Sync Enablement

## Goal

0.3.1 is intentionally narrow. Feature expansion is paused until Android can complete native Google authentication, establish an AUTH-1 session, and load real canonical data for daily use.

Target end-to-end path:

Android Credential Manager -> Google ID token -> AUTH-1 -> authenticated session -> canonical Dashboard/HORIZON/Finance/Notifications -> Room cache -> bounded WorkManager refresh.

Android remains independent of the Windows app and Windows Helper.

## Device evidence from 0.3.0

Observed on a physical Android device:

- backend reachable;
- AUTH-1 backend 2.6.5 reachable with enforcement ON;
- Google sign-in returned immediately as cancellation before an ID token was issued;
- user did not intentionally dismiss Google UI.

Therefore the failure occurs before AUTH-1 token validation and should not be treated as a backend-authentication failure.

## 0.3.1 client hardening

The Android sign-in coordinator now:

1. uses the explicit `GetSignInWithGoogleOption` flow for the user-initiated sign-in button;
2. uses an activity-based `MutableContextWrapper` for Credential Manager UI;
3. distinguishes a normal user cancellation from an immediate provider abort by elapsed time;
4. if the explicit flow aborts immediately, performs one bounded fallback using `GetGoogleIdOption` with `filterByAuthorizedAccounts=false` and auto-select disabled;
5. never loops or repeatedly retries provider UI;
6. includes stable diagnostic codes directly in the visible error text;
7. keeps the Web/server OAuth client ID as the ID-token audience;
8. does not weaken AUTH-1 or bypass backend authentication.

New important diagnostic:

- `IMMEDIATE_PROVIDER_ABORT` — both native Google identity flows terminate before user interaction / token issuance; verify Android OAuth client provisioning.

## Live-data success criteria

0.3.1 is not considered complete merely because CI passes. Physical-device PASS requires:

1. Google account UI appears and user can choose/sign in;
2. Android receives a Google ID token;
3. AUTH-1 accepts the token and displays authenticated identity;
4. canonical Dashboard becomes LIVE;
5. real Calendar and Tasks data render;
6. latest canonical HORIZON renders;
7. Finance and Notifications populate from canonical backend contracts;
8. data persists into Room cache;
9. app relaunch restores session while token is valid;
10. WorkManager performs bounded read-only refresh without requiring the PC/Windows Helper;
11. offline launch clearly uses CACHED/STALE data and remains non-mutating.
