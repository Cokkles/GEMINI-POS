# HORIZON V2.5 Rollback Procedure

Status: CURRENT FOR V2.5 MIGRATION

## Purpose

Provide a deterministic rollback path if production HORIZON contract cutover fails after runtime wiring.

## Rollback boundary

Rollback may restore the immediately preceding **current clean HORIZON production path** only. It must never restore any retired mechanism.

Forbidden rollback targets:

- `horizon_data.json`
- `refreshHorizonDataFeed()`
- `pruneHorizonJsonFile()`
- legacy `Planner.md`
- hard-coded snapshot/fallback payloads
- prior `latest_horizon_briefing` contents as factual input

## Before production cutover

1. Record the exact production HORIZON implementation/version being replaced.
2. Preserve the last known-good runtime configuration without changing source records.
3. Verify the current living briefing remains presentation output only.
4. Run the repository V2.5 synthetic matrix and read-only comparison.
5. Do not delete the immediately preceding clean runtime path until post-cutover validation passes.

## Rollback trigger conditions

Rollback is justified if the new runtime path:

- fails schema/interface validation;
- reads raw Journal Pad text;
- recalculates raw KINETIC ledger rows inside HORIZON;
- includes unmarked Notes & Ideas entries;
- consumes PRISM internals as finance state;
- reuses previous briefing content as evidence;
- fabricates unavailable source data;
- fails to update `latest_horizon_briefing` atomically/correctly;
- invokes a retired HORIZON artifact.

## Rollback action

1. Stop further V2.5 production executions.
2. Restore routing to the immediately preceding clean production HORIZON implementation only.
3. Confirm all retired-path kill guards remain active.
4. Do not restore stale data into `latest_horizon_briefing`; leave the last known-good briefing intact until a fresh valid run succeeds.
5. Record the failure, evidence, and restored runtime version in the GPOS repo.
6. Correct the defect on the V2.5 branch and repeat synthetic + read-only + controlled production validation.

## Exit from rollback

V2.5 cutover may resume only after the failed invariant is covered by a regression test and all migration gates pass again.
