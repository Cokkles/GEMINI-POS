# Apps Script 2.9.0 provisional nutrition and nightly KINETIC installation

Backend 2.9.0 removes Gemini from the immediate nutrition-capture path. Every
capture is written immediately with a provisional estimate and included in one
nightly review batch for its food-log day. Apps Script remains the system of
record; Gemini only reviews nutrition values. NotebookLM remains read-only.

## Safety and rollback

- Rollback source: backend 2.8.4.1, commit
  \`87cb31fc72d1285ca5b938ff8bda152175703880\`.
- Keep the existing production deployment URL.
- Do not enable the nightly trigger until the manual contract and capture tests
  pass.
- The update is additive. Nutrition columns A:X remain in their existing order.
- Three hidden sheets are created lazily in the existing nutrition spreadsheet:
  - \`_AEGIS_NUTRITION_RECONCILIATION_V1\`
  - \`_AEGIS_NUTRITION_EVIDENCE_V1\`
  - \`_AEGIS_NUTRITION_REVISION_AUDIT_V1\`
- No Drive archive or project-folder operation is part of this release.

## Script Properties

No new secret is required. The nightly reviewer uses the existing
\`GEMINI_API_KEY\`.

Optional model isolation:

\`\`\`text
AEGIS_NUTRITION_NIGHTLY_MODEL = gemini-3.5-flash
\`\`\`

The value above is the default and gives nightly nutrition a separate model lane
from the current HORIZON default.

Optional comma-separated official manufacturer domains:

\`\`\`text
AEGIS_NUTRITION_OFFICIAL_DOMAINS = examplemanufacturer.com,localrestaurant.com
\`\`\`

Only add domains that are genuinely controlled by the manufacturer or
restaurant. Retailers and aggregators must not be added merely because they show
a nutrition panel.

## Controlled capture test

Submit the exact five-item fixture with a new capture ID:

\`\`\`text
2 Servings Tyson Frozen Grilled Chicken, 2 servings Kirkland Salsa, 1 Medium Mission Flour Tortilla, 2 tablespoons Texas Pete Hotter Hot Sauce, 2 Servings Rice-A-Roni Chicken
\`\`\`

Expected immediate behavior:

- The API returns without waiting for Gemini.
- Exactly five provisional rows are written.
- The response remains compatible with existing clients through
  \`capture_status: CONFIRMED\`.
- The additive field reports
  \`nutrition_verification_status: PENDING\`.
- Column V for those rows reads \`ESTIMATED_PENDING\`.
- The reconciliation sheet contains one pending capture with all five items.
- No per-item Gemini request appears in the Gemini usage dashboard.

Resubmit the same capture ID and confirm that no duplicate rows are created.

## Controlled nightly test

After reviewing the five provisional rows, run:

\`\`\`text
runKineticNightlyNutritionReviewTodayV290()
\`\`\`

This performs one grounded Gemini request covering every pending capture recorded
for the current food-log date.

Expected behavior:

- Every capture ID receives exactly one review.
- Every item remains separate and in its original order.
- Small differences of at most 5% or 20 calories retain the provisional value and
  become \`VERIFIED\`.
- Meaningful well-supported differences become \`ADJUSTED\`.
- Differences over 30% supported only by weak evidence become
  \`NEEDS_REVIEW\`.
- Retailer or aggregator URLs cannot remain classified as \`OFFICIAL\`.
- The original and reviewed values are retained in the revision-audit sheet.
- The evidence catalog receives accepted medium/high-confidence recurring foods.
- The nutrition tracker and totals reflect accepted adjustments.
- A malformed, incomplete, 429, or 503 response preserves every provisional row
  and marks the batch \`DELAYED\`.

Run the function a second time. It should return \`NO_PENDING_ITEMS\` and must not
apply the batch twice.

## Enable nightly production scheduling

Only after the controlled nightly test passes, run once:

\`\`\`text
installAegisNutritionNightlyTriggerV290()
\`\`\`

Expected result:

- handler: \`runKineticNightlyNutritionReviewV290\`
- timezone: \`America/New_York\`
- schedule: once daily during the 2 AM hour
- duplicate triggers are removed

The scheduled controller reviews the oldest pending food-log date up to
yesterday. This allows a failed nightly batch to retry without discarding the
provisional data.

## Compatibility checks

- Android can submit and poll the existing durable capture routes.
- Legacy PWA \`/calories\` records a provisional entry without a synchronous
  Gemini request.
- Structured \`capture_nutrition\` uses the same provisional pipeline.
- Windows, Tasks, Calendar, HORIZON, Finance, RSS, and authentication continue
  operating normally.
- The next HORIZON document generation reads the reconciled tracker totals.
- NotebookLM requires no change because it remains a reader of the generated
  document.

A later Android checkpoint should display the additive verification status and
provide Dismiss, Edit and resend, Cancel, Clear resolved, and correction-history
controls.
