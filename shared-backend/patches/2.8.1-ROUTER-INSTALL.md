# Apps Script 2.8.1 nutrition router installation

The complete authoritative 2.8.0 `Code.gs` remains live-owned and is not reconstructed in Git.
Install `2.8.1-nutrition-reliability.gs` beside it, then make these two deliberate edits to the
authoritative source.

## 1. Version

```javascript
const AEGIS_BACKEND_VERSION = "2.8.1";
```

## 2. Protected POST route

Insert this route after `authorizeAegisPayload_` and before the legacy `/calories` message branch:

```javascript
if (action === "capture_nutrition") {
  return jsonOutput(handleAegisNutritionCaptureV281_(contents));
}
```

Add this scope mapping beside the other action mappings:

```javascript
if (action === "capture_nutrition") return "kinetic.read";
```

Add these capability flags without removing existing flags:

```javascript
ux_contracts: {
  nutrition_capture_v2: true,
  capture_reliability_v1: true
}
```

The Android payload deliberately carries both `action: "capture_nutrition"` and the legacy
`message: "/calories ..."`. An unchanged 2.8.0 deployment ignores the unknown action and follows
the legacy message route; 2.8.1 selects the structured idempotent route.

## Verification and rollback

1. Run `testAegisNutritionInputV281()`.
2. Run `testAegisNutritionValidationV281()`.
3. Deploy a new web-app version.
4. Verify `auth_config.backend_version` reports `2.8.1`.
5. Verify capabilities advertise both nutrition contracts.
6. Submit the same `capture_id` twice and confirm only one sheet row is written.
7. Confirm existing PWA `/calories` still uses its legacy response unchanged.

Rollback by selecting the prior Apps Script deployment version. Do not delete or reorder sheet
columns; A:J remain the legacy contract and K:X are additive provenance fields.
