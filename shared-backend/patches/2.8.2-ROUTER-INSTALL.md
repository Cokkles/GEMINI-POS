# Apps Script 2.8.2 durable nutrition queue installation

Install `2.8.2-durable-nutrition-queue.gs` beside the authoritative `Code.gs` and
`NutritionReliability281.gs`. Do not merge the files. Preserve the existing 2.8.1
`capture_nutrition` route and the legacy `/calories` message route.

## 1. Version

Change the authoritative version only when preparing the new deployment:

```javascript
const AEGIS_BACKEND_VERSION = "2.8.2";
```

## 2. Protected POST routes

Insert these routes after `authorizeAegisPayload_` succeeds and before the existing
`capture_nutrition` and legacy `/calories` branches:

```javascript
if (action === "enqueue_nutrition_capture") {
  return jsonOutput(enqueueAegisNutritionCaptureV282_(contents));
}
if (action === "get_nutrition_capture_status") {
  return jsonOutput(handleAegisNutritionCaptureStatusV282_(contents));
}
if (action === "retry_nutrition_capture") {
  return jsonOutput(handleAegisNutritionCaptureRetryV282_(contents));
}
```

Map all three actions to the existing nutrition authorization scope:

```javascript
if (
  action === "enqueue_nutrition_capture" ||
  action === "get_nutrition_capture_status" ||
  action === "retry_nutrition_capture"
) return "kinetic.read";
```

Advertise these additive capabilities without removing existing flags:

```javascript
ux_contracts: {
  nutrition_capture_v2: true,
  capture_reliability_v1: true,
  nutrition_capture_async_v1: true,
  nutrition_capture_status_v1: true,
  nutrition_result_cache_v1: true
}
```

Android 0.7.6 uses the asynchronous actions only when both async and status capabilities
are advertised. Older Android, Windows, and PWA clients continue using 2.8.1
`capture_nutrition` or legacy `/calories` unchanged.

## 3. Pre-deployment tests

Save the Apps Script project, then run these functions in order:

1. `testAegisNutritionInputV281()`
2. `testAegisNutritionValidationV281()`
3. `testAegisNutritionQueueV282()`
4. `testAegisNutritionStatusLifecycleV282()`
5. `testAegisNutritionIdempotencyV282()`
6. `installAegisNutritionQueueV282()`

The two integration tests delete only their own `V282-TEST-*` fixtures. The installer
creates or verifies the hidden `_AEGIS_NUTRITION_CAPTURE_QUEUE_V1` sheet, records the
stable nutrition data-sheet name in Script Properties, and ensures exactly one recurring
worker trigger exists.

## 4. Deployment validation

1. Create a new web-app deployment version; do not edit the existing 2.8.1 deployment in place.
2. Verify `auth_config.backend_version` is `2.8.2`.
3. Verify all five nutrition/reliability capabilities are `true`.
4. Enqueue a meal and record its returned `capture_id` and `capture_status`.
5. Query that ID until `CONFIRMED`; Android must not submit the meal again while it waits.
6. Enqueue the same ID and identical input again; verify `deduplicated: true` and no additional nutrition row.
7. Reuse the ID with different input; verify `CAPTURE_ID_CONFLICT` and no row.
8. Run a legacy PWA `/calories` capture and Windows/PWA/Android smoke tests.

## Rollback

Select the previous 2.8.1 web-app deployment version, then run
`removeAegisNutritionQueueTriggerV282()`. Preserve the queue sheet for diagnosis and recovery;
do not delete or reorder Nutrition columns. A:J remain legacy and K:X remain additive.
