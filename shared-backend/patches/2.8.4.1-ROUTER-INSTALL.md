# Apps Script 2.8.4.1 multi-item integrity installation

This is a narrow corrective update over 2.8.4. It prevents comma-separated or
line-separated foods from being certified as one generic combined meal.

## Replace only these installed files

1. Replace the complete `Code.gs` contents with `shared-backend/Code.gs`.
2. Replace the complete installed nutrition queue module contents with
   `shared-backend/patches/2.8.2-durable-nutrition-queue.gs`.
3. Replace the complete installed `NutritionProviderReliability284.gs` contents
   with `shared-backend/patches/2.8.4-nutrition-provider-hardening.gs`.

Do not add duplicate copies of those files. Leave the installed
`NutritionReliability281.gs` and `DeviceSessions283.gs` unchanged.

No Script Property changes are required. Existing optional model pins remain:

- `AEGIS_NUTRITION_SIMPLE_MODEL=gemini-3.5-flash-lite`
- `AEGIS_NUTRITION_GROUNDED_MODEL=gemini-3.6-flash`

## Pre-deployment tests

Run in this order:

1. `testAegisNutritionProviderRoutingV284()`
2. `testAegisNutritionMultiItemIntegrityV2841()`
3. `testAegisNutritionSimpleProviderV284()`
4. `testAegisNutritionFiveItemProviderV2841()`
5. `testAegisNutritionQueueV282()`
6. `testAegisNutritionIdempotencyV282()`
7. `testAegisNutritionStatusLifecycleV282()`
8. `testAegisDeviceSessionsV283()`

Tests 1 and 2 do not call Gemini. Test 3 makes one ungrounded request. Test 4
makes one grounded request for the exact five-item regression fixture but does
not write nutrition rows. Tests 6 and 7 automatically remove their sheet fixtures.

## Deployment verification

1. Edit the existing web-app deployment and select **New version**. Preserve its URL.
2. Verify `auth_config.backend_version` reports `2.8.4.1`.
3. Verify capabilities retain every earlier flag and add
   `nutrition_multi_item_integrity_v1: true`.
4. Submit the exact regression fixture with a new capture ID:

   `2 Servings Tyson Frozen Grilled Chicken, 2 servings Kirkland Salsa, 1 Medium Mission Flour Tortilla, 2 tablespoons Texas Pete Hotter Hot Sauce, 2 Servings Rice-A-Roni Chicken`

5. Accept only exactly five corresponding rows with preserved quantities.
6. Confirm no `Generic Mixed Meal`, `Mixed Meal Portion`, or other aggregate row
   is written.
7. Resubmit the same capture ID and confirm no duplicate rows.
8. Run legacy PWA `/calories` and Windows/Android compatibility smoke tests.

If the provider returns fewer than five items, loses a stated quantity, returns a
generic aggregate, or cannot adequately identify a branded source, the expected
behavior is `RETRY_SCHEDULED` with zero nutrition rows written.

## Existing inaccurate row

The already-written `Generic Mixed Meal Portion` row predates this validation and
must be manually removed from the active nutrition sheet if it should not count.
Do not reuse that capture ID with changed input.

## Rollback

Rollback is the last installed 2.8.4 deployment version. No sheet migration or
column removal is required.
