# Apps Script 2.11.1 KINETIC nightly reliability

Backend 2.11.1 is a corrective checkpoint on the consolidated 2.11.0 backend.
It preserves Calendar/Task usability, Android 0.8.0 compatibility, nutrition
A:X, AUTH-1, device sessions, HORIZON, and the 2.8.4.1 production rollback.

## Corrected behavior

- A log may say `retry scheduled` only after Apps Script creates the retry
  trigger successfully.
- Transient 429/503 failures use a real one-time trigger with bounded
  exponential delay and jitter.
- The nightly model lane can try a configured secondary model.
- Exact trusted catalog matches are reconciled locally without Gemini.
- Up to three overdue food dates drain per controller run by default.
- A 4 AM watchdog performs a second normal scheduler-path check.
- Three consecutive failures create one deduplicated AEGIS notification.

## Optional model configuration

The existing `AEGIS_NUTRITION_NIGHTLY_MODEL` remains the primary model.
Optionally set:

- `AEGIS_NUTRITION_NIGHTLY_FALLBACK_MODEL`
- `AEGIS_NUTRITION_NIGHTLY_MODEL_POOL` as a comma-separated ordered list
- `AEGIS_NUTRITION_NIGHTLY_MAX_DATES_PER_RUN` from 1 through 7

No configuration change is required to use the default bounded fallback.

## Controlled retry regression

1. Confirm a pending nutrition capture exists.
2. Temporarily configure an unavailable primary test model and a working
   fallback model.
3. Run `runAegisNutritionNightlyControllerV2111()`.
4. Confirm the provider attempt telemetry identifies both models.
5. For a controlled all-model capacity failure, confirm the result contains:
   - `status: DELAYED`
   - `retry_scheduled: true`
   - a non-null `next_attempt_at`
6. Confirm exactly one `runAegisNutritionNightlyRetryV2111` trigger exists.
7. Restore the production model properties.

## Install production triggers

After controlled regression passes, run:

```text
installAegisNutritionNightlyReliabilityV2111()
```

Confirm `getInstalledAegisTriggers()` contains exactly one daily
`runAegisNutritionNightlyControllerV2111` trigger and one daily
`runAegisNutritionNightlyWatchdogV2111` trigger. A retry trigger should exist
only while a transient retry is pending.

Edit the existing web-app deployment, select **New version**, and retain the
existing deployment ID and URL. Do not claim 2.11.1 deployed until runtime
health and a real scheduled-path result pass.
